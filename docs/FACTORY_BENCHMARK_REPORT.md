# ARIA 공정 시뮬레이션 정량 실험 — 2026-09-17

## 결론

이 구현은 제한된 DAG 공정에서 병목 변경의 효과를 재현하고 설명하는 연구용 프로토타입으로 활용할 근거가 있다. 상용 3D 시뮬레이터 대비 우수성, 실제 공장 예측 정확도, 실제 설비 고장 탐지 성능은 이번 실험으로 입증하지 않았다.

## 실험 조건

- 데모 공장 10개 컴포넌트, 30개 시드(0–29), 조건별 3,600초, 4조건 총 120회. 빈 공장부터 시작하며 워밍업을 제외하지 않았다.
- 모든 조건에서 동일 도착간격 2초, Machine MTBF 300초·MTTR 20초, MOCK 불량 확률 12%. 각 변경은 별도로 적용했다.
- 95% 신뢰구간은 30개 독립 시드 결과의 t 구간(df=29). 개선율은 시드별 기준 대비 변화율을 계산한 뒤 평균했다. 여러 조건을 탐색한 결과이며 외부 검증용 데이터는 없다.
- WIP는 각 자원 점유량의 시간 적분 합으로 계산한 시간 평균이다. 최종 WIP와 구분한다.
- 모형 구조 오차, 설비 비용, 물리 충돌, 실제 생산 데이터와의 오차는 포함하지 않는다.

## 생산 실험

| 조건 | 처리량/h (95% CI) | 양품/h | 리드타임 s | 평균 WIP | 버퍼 대기 s | Machine 활용률 | 처리량 변화 |
|---|---:|---:|---:|---:|---:|---:|---:|
| Baseline | 1117.7 [1109.9, 1125.5] | 984.5 | 49.10 | 15.35 | 15.95 | 93.3% | +0.00% |
| Machine capacity 2 | 1783.4 [1780.5, 1786.3] | 1570.5 | 14.54 | 7.22 | 1.88 | 74.4% | +59.61% |
| Processing time 2s | 1676.6 [1664.9, 1688.4] | 1476.6 | 32.91 | 15.40 | 10.02 | 93.3% | +50.01% |
| Buffer capacity 20 | 1117.7 [1109.9, 1125.5] | 984.5 | 95.05 | 29.92 | 62.65 | 93.3% | +0.00% |

용량 2 조건의 시드별 처리량 증가율 평균은 **59.61%**, 95% CI는 **58.58–60.64%**다. 버퍼 확대는 처리량 개선 없이 리드타임과 WIP를 늘렸다.

![실험 비교](images/factory_benchmark.png)

용량 2는 병렬 처리 슬롯을 늘린 가정이며 실제 로봇팔 한 대가 두 작업을 동시에 처리한다는 뜻은 아니다. 시간 2초 조건 역시 공정 개선의 가정이다. 투자비·설비 공간·안전성 검증을 거친 최적해로 해석해서는 안 된다.

## 엔진 정확성 및 반복성

- 생산 실험 120회와 확장 실험 9회(시간 예산 도달 시점 포함)에서 `생성 수 = 완료 수 + WIP` 확인. 생산 120회에서 최종 자원 점유량이 용량 이하임을 확인. 중간 상태 전부의 용량 검증은 기존 단위 테스트와 별개이다.
- 고장·불량 없는 모델을 동일 시드로 재실행해 모든 반환 지표가 일치했다. 다음 오차는 빈 공장 출발·관측 종료 시 재공품에 따른 정상상태 이론값 대비 차이다.

| Machine 용량 | 이론 정상상태 처리량/h | 1시간 관측 처리량/h | 상대 차이 |
|---|---:|---:|---:|
| 1 | 1200 | 1197.0 | -0.250% |
| 2 | 1800 | 1795.0 | -0.278% |

## 순찰 및 보고

30가지 순찰 시작 위치/위상에서 Machine 고장 60초를 주입했다. .25초 간격의 가속된 결정론적 순찰 시계를 사용했다. 아래 시간은 모델 내 순찰 경과 시간이며 네트워크·브라우저·실제 로봇 이동의 벽시계 지연이 아니다.

- 고장 보고 생성: 30/30; 현장 확인: 30/30.
- 현장 확인 시간: 평균 4.12초, 범위 0.25–11.00초.
- 보고 감지 최대 지연: 0.25초; 복구 기록 최대 지연: 0.00초.
- 고장 주입 전 DOWN 오탐: 0건. 제한된 정상 DES 상태 관측이므로 센서 기반 탐지 precision/recall로 해석하지 않는다.

보고는 엔진의 DOWN 상태를 읽는 구조이므로 실제 장비의 고장을 독립적으로 추론하는 시험이 아니다.

## 계산 확장성

같은 데모 라인을 독립적으로 복제한 10·30·100개 컴포넌트, 각 3개 시드의 1시간 실행을 시도하고 서비스 기본값과 같은 실행당 10초 예산을 적용. 연결이 복잡한 단일 공장이나 100개 설비의 3D 렌더링 시험이 아니다. 최초 무제한 배치는 완료되지 않아 중단했고, 아래 원자료는 웹 측정 종료 후 워크스테이션에서 다시 실행한 유한 예산 배치다. 중단한 실행은 결과에 합산하지 않았다. 시간 제한을 넘긴 경우 부분 진행 시점의 지표만 기록한다.

| 컴포넌트 | 10초 내 1시간 완주 | 진행된 시뮬레이션 시간 평균 s | 실행 시간 중앙값 s |
|---|---:|---:|---:|
| 10 | 3/3 | 3600.0 | 0.313 |
| 30 | 3/3 | 3600.0 | 2.951 |
| 100 | 0/3 | 688.7 | 10.018 |

## 실제 웹 조작 및 3D 화면

최초 엔진 배치를 일시정지한 뒤 별도로 Reset → Run → 설비 선택 → Cell close-up → Top → Pause를 실제 웹 UI에서 실행했다. 저장된 사용자 공장은 18개 컴포넌트이며 생산 실험의 데모 10개와 다르다. 각 보기에서 5초짜리 rAF 간격 측정을 3회 했다.

- 렌더러: `ANGLE (Google, Vulkan 1.3.0 (SwiftShader Device (Subzero) (0x0000C0DE)), SwiftShader driver)`
- 뷰포트: 1144 × 508; Headless Chrome 134. GPU 가속 데스크톱 브라우저의 결과가 아니다.

| 보기 | FPS 평균 (3개 창) | FPS 범위 | 프레임 간격 p95 평균 ms |
|---|---:|---:|---:|
| overview | 9.5 | 5.6–12.3 | 188.9 |
| cnc_cell | 11.1 | 10.7–11.4 | 194.4 |
| top | 11.7 | 11.3–12.1 | 166.7 |

스냅샷 fetch+JSON 파싱 20회: 중앙값 506.5 ms, p95(최근접 순위) 562.4 ms. 렌더링 중 브라우저 주 스레드 대기를 포함하며 서버 단독 처리 시간은 아니다.

해당 UI 실행에서 브라우저 예외와 HTTP 오류는 0건이었다.

rAF 빈도는 GPU 프레임 완료 시간을 측정하지 않는다. 소프트웨어 렌더링 결과만으로 3D 사용성이 탁월하다고 결론 낼 수 없다. 30/60 FPS 목표는 실제 GPU 환경에서 별도 장시간 측정해야 한다.
