# ARIA 디지털 트윈 재설정 명세 v3

2026-10-13 Asia/Seoul. 사용자 확정 계약. 본 실행은 사용자 확인 전까지 보류한다.

ARIA 연구 실행은 **정책 A의 DES 원자료 생성 → 정책 B와 재검사 변형의 사후 계산 → 1,000개당 부하·품질·비용 평가**로 정리한다. 기존 코드·데이터와 유효 파일럿을 보존한다. 첨부 원문과 v2의 7,020회 DES 계획보다 이번 사용자 확정 조건을 우선한다.

## 1. 실행 수와 범위

| 구분 | 조건 | 수량 |
|---|---|---:|
| 기준 A DES | 3클래스 × 3모델 × 5셀·속도 × 2지연 모드 × 30시드 | 2,700 |
| 기존 A 재사용 | 유효 파일럿의 A 15개, 입력·원자료 해시 확인 | 15 |
| 새 기준 A | 기준 A에서 유효 재사용 제외 | 2,685 |
| 상한 확인 A | 3클래스 × 3모델 × 30시드, inline 2m/s, profile | 270 |
| 신규 DES 합계 | 기준 A 신규 + 상한 확인 | 2,955 |
| 기본 B 사후 계산 | 기준 A마다 assumed 사람 1명·30초·민감도/특이도 1.0 | 2,700 |
| B 단일 요인 변형 | inline 0.5m/s·profile, 6변형 × 3모델 × 30시드 × 3클래스 | 1,620 |

클래스는 bottle·screw·carpet, 모델은 coreset·ccifps·random_same_k다. 기준 셀·속도는 robot 0.5m/s 및 inline 0.25·0.5·0.75·1.0m/s다. 모든 DES는 정책 A, 시드 0–29, 3,600초 실행과 600초 워밍업을 사용한다.

상한 확인은 270개 고유 조건이다. 기존 분위수 기반 표시 참조 1,080행을 별도 실행하지 않는다. seed0 비용 탐색 9개는 270개에 포함되며 이번 작업에서 실행하지 않는다. 속도 상한 2m/s는 가정이다. 클리핑된 속도로 1−q의 HOLD 확률을 주장하지 않는다.

B 변형은 재검사 10·60초, 민감도 0.98·0.95, 특이도 0.98·0.95를 각각 하나씩 변경한다. 상한 확인에는 B 변형을 추가하지 않는다. 비용 비율 5:1·20:1·100:1도 사후 계산이며 DES 수를 늘리지 않는다.

## 2. 소스와 판정 경계

`configs/line_profile.yaml`의 defect_rate=0.05, source=assumed를 유지한다. 평가기는 GT로 정상·불량 풀을 사전에 만들고 독립 난수로 Bernoulli 5% 선택 및 풀 안 균등 복원추출을 수행한다. 실제 관측 불량률이 정확히 5%가 되도록 결과를 수정하지 않는다.

AI replay는 고정 소스 스케줄의 이미지 ID에 대응하는 예측·임계값을 소비한다. GT는 소스 준비·평가·사람 oracle의 라벨 판단에만 사용한다. 정상 calibration 임계값과 실측 프로파일을 유지하고 모델 선택이나 성능 수치를 새로 최적화하지 않는다.

## 3. B 사후 계산

사후 계산은 저장된 A의 `mainline_exit_time`과 NG 판정을 오프라인 FCFS 큐의 도착으로 사용한다. 워밍업 이전 도착도 계산해 잔류 큐와 활용률을 보존한다. 기본 인원은 1명이며 본 라인의 투입·판정·분기에 되먹임하지 않는다. HOLD와 AI가 통과시킨 FN은 재검사 대상으로 바꾸지 않는다.

구현은 `aria/simulation/dt/posthoc.py`에 둔다. 기존 `tools/dt_posthoc_reinspection.py`는 호환 import다. B 원자료는 기존 15쌍 일치 검증에만 사용하며 신규 B DES 실행은 차단한다. 레거시 엔진의 B 지원은 기존 동작·검증용으로 보존한다. 현재 HMI 미리보기는 이번 연구 실행 전환 대상이 아니다.

원자료를 변형하지 않고 별도 출력 폴더에 결과를 저장한다. 입력 A 원장의 완료 manifest·원자료 hash·GT hash를 확인한다. 출력에는 입력 run 경로·완료 hash·사후 구현 hash와 `new_DES_runs=0`을 기록한다.

## 4. 정규화 지표

분모 N은 관측 창 `[600,3600]`에서 본 라인을 떠난 부품 수이며 HOLD를 포함한다. 분모가 0이면 정규화 값은 null이다.

- NG/1,000 = NG 도착 수 ÷ N × 1,000.
- 오탐/1,000 = 정상품 NG 수 ÷ N × 1,000.
- 인시/1,000 = NG 도착 수 ÷ N × 1,000 × 가정 재검사 초 ÷ 3,600.

큐 평균·최대·종료 잔량, 미완료 대기 나이, 실제 관측 완료 수와 활용률도 함께 보존한다. 필요 인원 `floor(도착률 × 서비스시간)+1`은 rho<1을 위한 부하 추정이며 실측 인력 생산성이나 SLA 보장이 아니다. 낮은 완료 비용을 재검사 잔량과 분리해 성능 개선으로 주장하지 않는다.

## 5. 보존과 실행 구조

작업 브랜치는 `dt-wip-20261013`이다. 첫 보존 커밋은 `0e5420c`이며 main은 변경하지 않는다. 대용량 검증 자료는 기존 경로에 유지하고 `docs/provenance/dt-wip-20261013/external_artifacts.json`에 경로·바이트·SHA-256을 남긴다.

현행 계획은 `aria/simulation/dt/plan.py`, 계획 출력은 `tools/run_dt_matrix.py`, 저장 A의 사후 계산은 `tools/postprocess_dt.py`가 담당한다. 기존 7,020회 DES 실행·집계 도구와 초기 개정안은 `archive/dt_legacy_20261013/`에 보존하고 INVALID 실행 구조로 표시한다. 과거 유효 P1·15쌍 파일럿까지 무효화하는 것은 아니다.

계획 생성은 새 DES를 실행하지 않는다. `--execute`는 사용자 확인 전까지 실패한다. 본 실행 재개 시 8시간 견적, 저장량 15% 여유 + 2GiB, 상한 seed0 실측, 파일럿 사후 계산 일치를 확인한다. 최신 계획의 약 6.3–6.4시간은 과거 외삽 추정이며 상한 실측 완료값이 아니다.

## 6. 이번 인수 기준

1. 기존 미커밋 작업의 보존 커밋과 대용량 자료 manifest.
2. 정책 A 전용 계획, 상한 270개 고유 조건, 5% 복원추출과 사후 B 정규화.
3. 비전 골든 diff 0과 기존 constant DES 기준 6조건 바이트 일치.
4. 백엔드 전체 테스트 실행 및 선택적 PostgreSQL 통합시험의 실행 여부 구분.
5. 저장 파일럿 15쌍의 B 사후 계산과 실제 B 원자료 일치.
6. filesystem MCP의 프로젝트 루트 및 sandbox 경로 회귀 시험.

filesystem MCP는 `Path(__file__).resolve().parents[3]`로 프로젝트 루트를 계산한다. 다른 MCP의 같은 패턴은 목록만 보고하고 별도 확인 전에는 수정하지 않는다. AGENTS.md·TOOLS.md·SKILL.md는 수정하지 않는다.

화면의 바닥·프리팹·M0609·CAD GLB·카메라·패널, 기본 화면 전환, 전체 연구 본 실행, 추가 P1 측정은 이번 범위에서 제외한다.
