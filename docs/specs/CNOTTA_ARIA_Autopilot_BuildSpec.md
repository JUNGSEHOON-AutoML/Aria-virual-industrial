# CNOTTA × ARIA — 오토파일럿 BuildSpec

작성 2026-10-13 · 기준 브랜치 `dt-dashboard-p6`(`157c364` 이후) → 작업 브랜치 `dt-cnotta` · 작업 규칙 `AGENTS.override.md`

## 0. 결론

CNOTTA 브랜드의 검사 공정 디지털 트윈 대시보드를 **M0부터 M6까지 Codex가 스스로 이어서 완성**한다. 사람이 확인하는 시점은 두 번뿐이다: M1 화풍(실제 GPU 화면), M6 최종 데모.

- 레퍼런스 영상을 따라 그리지 않는다. 레퍼런스 프레임 비교는 게이트에서 뺀다(파일은 gitignore 상태로 두되 사용하지 않음). 기준은 이 문서의 CNOTTA 디자인 시스템이다.
- 모든 게이트는 스크립트로 자동 판정한다(`tools/gates/m{n}.py` → `docs/autopilot/gates/m{n}.json`). 사람 눈으로만 판단하는 게이트는 M1의 화풍 하나다.
- M1 화풍 승인을 기다리는 동안 M2–M4를 계속 진행한다. 화풍 피드백은 토큰·프리팹 범위에서만 반영되도록 구조를 잡는다.

## 1. CNOTTA 디자인 시스템

### 1.1 브랜드 해석

로고는 둥근 고리에 홈이 하나 난 원형 마크(눈금 하나가 있는 다이얼)와 굵은 남색 워드마크다. 여기서 세 가지를 가져온다.

- **다이얼**: KPI는 숫자 카드가 아니라 고리형 게이지로 표시한다. 선택 핀도 물방울 대신 "홈 난 고리" 마커를 쓴다.
- **남색 + 페리윙클 2색 체계**: 무게는 남색이, 강조는 페리윙클이 맡는다. 레퍼런스처럼 진한 파랑으로 건물을 칠하지 않는다.
- **둥근 기하**: 모서리 반경을 크게, 선은 굵고 끝이 둥글게.

### 1.2 토큰 (`frontend/src/brand/cnotta.tokens.json`에 한 번만 정의)

로고 이미지에서 샘플링한 값을 기준으로 정했다. 원본 로고 파일을 받으면 `brand.ink`·`brand.primary`만 원본 값으로 바꾼다.

| 토큰 | 값 | 용도 |
|---|---|---|
| brand.ink | `#10295E` | 워드마크, 제목, 3D 설비의 짙은 포인트(다리 끝·받침) |
| brand.primary | `#5E66F4` | 강조, 선택, 벨트, 진행 막대, 다이얼 |
| brand.primary-100 | `#EEF0FE` | 선택 배경, 칩 배경 |
| brand.primary-200 | `#DDE1FD` | 구역 바닥 표시, 비활성 게이지 트랙 |
| surface | `#F7F8FC` | 앱 배경, 3D 외곽 지면 |
| floor | `#FFFFFF` | 건물 내부 바닥 |
| line | `#E3E6F0` | 통로선, 카드 경계 |
| equip | `#FFFFFF` + `#E9ECF5` | 설비 본체(흰색)와 프레임(연회색) |

규칙: 판정 3색은 부품·판정 칩에만 쓴다. 한 화면에서 `brand.primary` 면적은 10% 이하로 한다. 나머지는 흰색·남색·회색이 맡는다.

### 1.3 형태와 빛

- 3D: 흰 설비 + 페리윙클 벨트 + 남색 받침. `RoundedBox` 반경 0.06–0.12. 건물은 흰 외벽에 남색 상단 띠, 높이 2.4m 이하의 절개 벽.
- 지면 `surface`, 건물 바닥 `floor`, 구역은 `primary-200` 반투명 바닥판과 둥근 모서리 경계선으로 표시한다.
- 빛: `NoToneMapping`, sRGB 출력. ambient 0.6 + hemisphere 0.4 + directional 0.9(그림자) + `ContactShadows` opacity 0.35. 렌더된 지면·바닥 픽셀이 토큰 값에서 채널당 ±6 이내여야 한다(자동 게이트).
- 카메라: 정사영, 방위 45°, 내려다보기 35°, 회전 ±20°, 클릭 시 0.6초 fly-to.
- UI: 카드 반경 16px, 그림자 `0 6px 24px rgba(16,41,94,0.08)`, 글꼴 Pretendard(기존 로컬 파일). 숫자는 tabular-nums.
- 브랜드 표시: 상단 바 좌측 CNOTTA 로고 + "ARIA Inspection Twin". 건물 외벽 한 곳에 로고 마크 데칼. 그 외 반복 노출 금지.
- 로고 파일: 원본이 없으면 마크(홈 난 고리)를 SVG로 임시 제작해 `frontend/public/brand/cnotta-mark.svg`에 두고 `DECISIONS.md`에 "임시 로고, 원본 교체 필요"로 기록한다.

## 3. 장면 배치

D0 평면 배치를 유지하되 아래를 바꾼다.

- 카메라를 당겨 라인·로봇 셀·재검사 구역이 기본 시점 화면의 70% 이상을 채운다.
- 재검사 구역을 본 라인에서 통로 1개(약 2m) 떼어 놓는다. NG 레인은 구역 입구의 대기 랙 앞에서 끝난다. 레인과 랙·작업대 바운딩박스 겹침 0.
- 라벨 칩은 INFEED·VISION·SORT·OFFLINE REINSPECTION·ROBOT CELL 다섯 개만 둔다. 좌상단 큰 제목은 제거한다.
- 폐기 빈은 위가 열린 상자 모양. 바닥 통로선과 구역선을 넣는다.
- 트럭·도로·나무는 장식이며 클릭되지 않는다. 트럭 측면에는 CNOTTA 마크만 넣는다.

## 4. 데이터 계약

새 읽기 전용 API. DES를 실행하지 않는다.

| API | 반환 |
|---|---|
| `GET /api/dt/runs` | 재생 가능한 실행 목록: run_id, 클래스, 모델, 셀·속도, 지연 모드, seed, 완료 hash |
| `GET /api/dt/runs/{id}/timeline?from=&to=` | 부품 구간(투입·검사·판정·분기·출구 시각, 경로, 판정), 설비 상태 전이, 재검사 대기열 시계열(기본 B 사후 결과) |
| `GET /api/dt/runs/{id}/kpi?t=` | 시각 t까지의 KPI. `evaluation.py`·`posthoc.py`와 같은 함수로 서버에서 계산 |
| `GET /api/dt/results/summary` | 본 실험 요약(95% CI). 없으면 404 → 화면은 "실험 진행 중" 표시 |

- 부품 위치는 구간 시각 사이를 레인 polyline으로 보간한다. 부품은 `InstancedMesh` 하나로 그린다.
- 재검사 랙의 박스 수 = 해당 시각의 사후 계산 대기열 길이. 랙 용량을 넘으면 바닥에 쌓고 숫자 배지.
- 개발·데모는 파일럿 실행(`docs/validation/aria_dt_20261013_03/des_pilot30/`)을 쓴다. 본 실험이 끝나면 결과 폴더만 추가한다.

## 9. 캠퍼스 맵

### 9.1 결론

큰 맵은 **장식이 아니라 비교 장치**로 만든다. 캠퍼스의 건물 하나는 검사 홀 하나이고, 각 홀 안에는 같은 부품 흐름을 받는 레인 3개(코어셋·CCIFPS·랜덤 동일-K)가 나란히 있다. 같은 시드의 부품이 세 레인에 동시에 들어가고, NG 레인과 재검사 랙이 모델마다 다르게 차오르는 모습이 한눈에 보인다. 홀은 클래스별로 3개(bottle·screw·carpet)다.

### 9.2 구조: 두 단계 시점

| 단계 | 보이는 것 | 진입 |
|---|---|---|
| 캠퍼스 | 홀 3개 + 로봇 셀 동 + 물류 야드 + 도로·나무, 각 홀 지붕 위 다이얼 배지(오탐/1,000) | 기본 시점, 상단 바 "캠퍼스" |
| 홀 | 레인 3개, 공유 투입부, 홀 전용 재검사 구역 | 홀 클릭 또는 상단 바 홀 선택, 0.8초 fly-to |

- 건물 지붕은 캠퍼스 시점에서 보이고, 홀 시점으로 들어가면 지붕이 페이드아웃된다(절개 벽 유지).
- 홀 시점의 패널(다이얼 KPI·상세 카드·자원 탭)은 해당 홀 기준이다. 캠퍼스 시점의 패널은 3개 홀 요약이다.
- 미니맵(우하단 작은 평면도, 현재 시야 사각형 표시)을 둔다. 미니맵 클릭으로 이동.

### 9.3 맵 정의는 데이터로

`frontend/src/campus/campus.layout.json` 하나가 맵 전체를 정의한다. 장면 코드는 이 파일을 읽어 조립만 한다.

```json
{
  "units": "m",
  "sites": [
    {"id": "hall-bottle", "kind": "inspection_hall", "class": "bottle", "origin": [0, 0], "rotation": 0,
     "lanes": ["coreset", "ccifps", "random_same_k"], "run_selector": {"seed": 0, "cell": "inline", "speed": 0.5}},
    {"id": "hall-screw", "kind": "inspection_hall", "class": "screw", "origin": [48, 0], "rotation": 0},
    {"id": "hall-carpet", "kind": "inspection_hall", "class": "carpet", "origin": [96, 0], "rotation": 0},
    {"id": "robot-cell", "kind": "robot_cell", "origin": [24, 40]},
    {"id": "yard", "kind": "logistics_yard", "origin": [72, 40], "decorative": true}
  ],
  "roads": [[[-20, -16], [140, -16]], [[60, -16], [60, 70]]],
  "foliage_seed": 7
}
```

- 홀 하나는 M1에서 만든 `Site` 컴포넌트를 재사용하되 레인 수를 `lanes` 길이만큼 늘린다. 홀 치수는 레인 수와 CAD `dims.json`에서 계산한다.
- 나무·박스·팔레트 배치는 `foliage_seed`로 고정한다. 새로고침해도 같은 맵이 나와야 한다.
- 장식 구역(`decorative: true`)은 클릭되지 않고 데이터와 연결하지 않는다.

### 9.4 데이터 연결

- 홀의 세 레인은 같은 클래스·셀·속도·시드의 세 모델 실행을 동시에 재생한다(`/api/dt/runs`에서 `run_selector`로 고름). 투입 스케줄이 같으므로 세 레인의 투입 부품 ID는 같아야 한다(자동 게이트).
- 캠퍼스 배지와 요약 패널은 `/api/dt/runs/{id}/kpi`를 홀별로 모은 값이다. 본 실험 결과가 있으면 `/api/dt/results/summary`의 30시드 평균과 95% CI를 쓴다.
- 재생 시계는 캠퍼스 전체가 하나를 공유한다.

### 9.5 성능 규칙 (큰 맵의 핵심)

| 규칙 | 방법 |
|---|---|
| 반복 물체는 인스턴싱 | 나무·박스·팔레트·롤러·펜스 기둥은 종류별 `InstancedMesh` 하나 |
| 정적 형상 병합 | 홀 외벽·바닥·도로는 홀별로 `mergeGeometries`해 draw call 축소 |
| 거리별 상세도 | drei `Detailed`: 가까이 = 전체 형상, 멀리 = 단순 박스. M0609는 캠퍼스 시점에서 단순 모형 |
| 지연 로딩 | 홀 내부 상세(로봇 메시, 작업자, 랙 박스)는 홀 시점 진입 시 `Suspense`로 로드 |
| 그림자 | 방향광 그림자는 현재 시야 범위로 제한, 먼 곳은 `ContactShadows`만 |
| 렌더 빈도 | 재생 중이 아니면 `frameloop="demand"` |
| 카메라 경계 | 캠퍼스 바운딩박스 밖으로 이동 금지, 줌 최소·최대 제한 |

### 9.6 M7 게이트

| 항목 | 기준 |
|---|---|
| 맵 정의 | 장면의 모든 사이트·도로가 `campus.layout.json`에서 생성(하드코딩 좌표 0), 같은 seed 재로드 시 소품 배치 동일 |
| 비교 정합성 | 각 홀 3레인의 투입 부품 ID 시퀀스 동일, 레인별 NG 수 = 해당 run timeline |
| 성능(실제 GPU) | 캠퍼스 시점 재생 중 50 FPS 이상, draw call 300 이하, 홀 진입 지연 1초 이하. Codex 환경에서는 draw call·삼각형 수만 측정하고 FPS는 "실제 GPU 미확인"으로 보고 |
| 상호작용 | 홀 클릭 → fly-to → 지붕 페이드, 미니맵 이동, 장식 클릭 0 |

### 9.7 순서

M1–M6을 먼저 끝낸다(홀 하나가 완성된 상태). M7은 그 홀을 레인 3개로 넓히고 캠퍼스로 복제한다. 단, M1에서 `Site` 컴포넌트가 원점·회전·레인 목록을 인자로 받도록 만들어 두면 M7에서 장면 코드를 다시 짜지 않아도 된다(M1 구현 시 반영).
