# ARIA_DT_P6_Dashboard_BuildSpec — 레퍼런스형 디지털 트윈 대시보드

작성 2026-10-13 · 기준 브랜치 `dt-wip-20261013` · 선행 문서 `docs/specs/ARIA_DT_Reset_BuildSpec_v3.md`

## 0. 결론

화면은 **실험과 분리해서 지금 바로 시작**한다. 3D는 라이브 DES가 아니라 **저장된 정책 A 실행 원자료를 재생(replay)** 해서 움직인다. 그래서 본 실험이 돌아가는 중에도 기존 파일럿 15개로 화면을 만들 수 있고, 실험이 끝나면 결과 파일만 바꿔 끼운다.

지난 시도에서 "공중에 뜬 상자"가 나온 원인은 세 가지였다. 바닥·건물·소품 같은 장면 구성이 명세에 없었고, 화풍을 확인하는 게이트가 없었고, 렌더링 확인을 소프트웨어 렌더러(SwiftShader)로만 했다. 이번 명세는 단계마다 **레퍼런스 프레임과 나란히 놓은 캡처**를 게이트로 둔다.

## 3. 장면 구성 (평면도, 단위 m)

```
 y↑
  8 ┌─────────────── 검사동 건물(반쪽 벽, 남·동쪽 벽 생략) ───────────────┐
    │  [로봇 셀]  M0609 받침대 + 인피드/아웃피드 컨베이어 + 안전펜스       │
  4 │                                                                       │
    │  투입 → 컨베이어 6m → [비전 부스] → 컨베이어 2m → [분류기] ─┬→ OK 레인 → 포장·팔레트 │
  0 │  (팔레트 더미)          (카메라·조명터널·엣지 GPU 랙)        ├→ NG 레인 → [오프라인 재검사 구역] │
    │                                                               └→ HOLD 케이지              │
 -4 │  [오프라인 재검사 구역] 작업대 + 작업자 + 대기 랙(대기열 길이만큼 박스 적재) + 폐기 빈 │
 -8 └───────────────────────────────────────────────────────────────────────┘
      외곽: 도로, 출하 도크와 트럭 1대(장식), 나무 6~10그루
```

- 레인·부스·분류기 치수는 `assets/cad/*/dims.json`에서 읽는다. 화면용 모형은 같은 치수의 단순화 모델(RoundedBox 조합)이다.
- **재검사 대기열은 랙 위 박스 개수로 보여 준다.** 정책 B 사후 계산 결과의 시각별 대기열 길이에 맞춰 쌓인다. 랙 용량을 넘으면 바닥에 쌓고 숫자 배지를 띄운다. 이 구역이 본 라인을 막지 않는다는 점이 화면에서 바로 보여야 한다.
- 트럭·도로·나무는 장식이다. 데이터와 연결하지 않고, 상세 카드도 열지 않는다.

| accent-orange | `#F29A38` | 작업자 조끼 등 사람 관련 |
| tree | `#4CB782` | 나무 |
| ok / ng / hold | `#22A06B` / `#E5484D` / `#F5A524` | 부품 판정 색. 판정에만 쓴다 |
| pin | `#3B6FF6` | 선택 핀 |

- 재질: `MeshStandardMaterial`, roughness 0.85, metalness 0. 텍스처를 쓰지 않는다(로고 데칼 제외).
- 모서리: drei `RoundedBox`, radius 0.04–0.1.
- 빛: ambient 0.55 + hemisphere 0.35 + directional 1.1(그림자 on, shadow map 2048) + drei `ContactShadows`. `Environment preset="city"` intensity 0.25. 톤매핑 ACES Filmic.
- 카메라: drei `OrthographicCamera` + `CameraControls`. 방위 45°, 내려다보는 각 약 35°. 회전은 ±20°만 허용, 줌·패닝 허용. 클릭 시 0.6초 fly-to.
- 패널: 흰 카드, 모서리 12px, 그림자 `0 4px 16px rgba(30,63,168,0.08)`, 글꼴 Pretendard 하나. 패널은 캔버스 위에 절대 위치로 띄우고 3D 영역을 밀어내지 않는다.

외부 무료 에셋(예: CC0 저폴리 팩)을 쓰려면 받기 전에 라이선스를 확인하고 `assets/third_party/<이름>/LICENSE`와 출처를 남긴다. 확인 전에는 코드로 만든 도형만 쓴다.

## 5. 데이터: 저장 실행 재생

새 API (읽기 전용, DES를 실행하지 않음):

| API | 반환 |
|---|---|
| `GET /api/dt/runs` | 재생 가능한 실행 목록: run_id, 클래스, 모델, 셀·속도, 지연 모드, seed, 완료 hash |
| `GET /api/dt/runs/{run_id}/timeline?from=&to=` | 부품별 구간(투입·검사·판정·분기·출구 시각, 경로, 판정), 설비 상태 전이, 재검사 대기열 시계열(기본 B 사후 결과) |
| `GET /api/dt/runs/{run_id}/kpi?t=` | 시각 t까지의 KPI. **평가기(`evaluation.py`, `posthoc.py`)와 같은 함수로 서버에서 계산** |
| `GET /api/dt/results/summary` | 본 실험 완료 후 모델 비교표(95% CI). 없으면 404, 화면은 "실험 전" 표시 |

- 부품 위치는 구간 시작·끝 시각 사이를 레인 경로(polyline)를 따라 보간한다. 화면이 자체 타이머로 공정을 만들지 않는다.
- 재생 컨트롤: 재생/일시정지, 1×·10×·60×, 시간 슬라이더, 실행 선택.
- 부품은 `InstancedMesh` 하나로 그린다(수천 개 대비). 판정 색은 인스턴스 색으로 바꾼다.
- GT는 화면에 보내지 않는다. 단 "GT 기준 품질률" KPI 값은 서버 평가기가 계산해서 숫자로만 보낸다.

## 7. 단계와 게이트

모든 캡처는 **실제 GPU 브라우저**에서 1440×900으로 찍는다. Codex 환경이 소프트웨어 렌더러면 캡처를 사용자가 자기 PC에서 찍어 확인한다. SwiftShader 캡처는 게이트 근거가 아니다.

1. **D0 룩데브 (데이터 없음)**
    - 할 일: 3절 평면 배치, 4절 토큰, 건물·소품·카메라·빛. 부품은 고정 위치 몇 개.
    - 산출: 고정 시점 3장(전체, 검사 라인, 재검사 구역)을 `ref_01`·`ref_03`과 나란히 놓은 비교 이미지.
    - 게이트: **사용자가 화풍을 승인**. 공중에 뜬 객체 0개, 모든 설비가 바닥에 붙어 있음.
2. **D1 재생**
    - 할 일: 5절 API와 재생 컨트롤. 파일럿 실행 하나로 부품이 레인을 따라 이동.
    - 게이트: 같은 시각에서 화면 부품 수 = 서버 timeline의 진행 중 부품 수. 일시정지 시 위치 고정. 10× 재생 시 순서 유지.
3. **D2 상호작용**
    - 할 일: 핀, 클릭 선택, fly-to, 객체별 상세 카드, 검색으로 부품 찾기.
    - 게이트: 부품 클릭 → 카드의 점수·판정이 `per_image.csv`와 일치. 장식 객체는 클릭되지 않음.
4. **D3 패널**
    - 할 일: KPI 카드, 수명주기 단계, 자원 탭, 재검사 랙 적재.
    - 게이트: KPI 카드 숫자 = `/kpi` 응답 = 오프라인 평가 결과(같은 run, 같은 t). 재검사 랙 박스 수 = 사후 계산 대기열 길이.
5. **D4 비교 보기와 마감**
    - 할 일: 본 실험 결과가 생기면 비교 보기 연결. 없으면 "실험 전" 상태.
    - 게이트: 실제 GPU에서 50 FPS 이상(전체 보기, 부품 500개 이상 재생 중), 콘솔 예외 0, 30초 화면 녹화.

## 8. 금지

- 화면이 자체 타이머나 난수로 공정·판정·대기열을 만들지 않는다.
- 측정하지 않은 숫자를 화면·문서에 쓰지 않는다. 가정값에는 `assumed` 배지를 붙인다.
- 실존 회사 이름·로고를 쓰지 않는다. 레퍼런스 영상의 브랜드("WareTrack" 등)를 쓰지 않는다.
- 연구 원자료, DES 엔진, 평가기, 사후 계산 코드를 화면 작업 때문에 바꾸지 않는다. 필요한 값은 새 읽기 API로만 가져온다.
- 레퍼런스 프레임을 커밋하지 않는다.

## 9. 보고 형식

단계마다: 바꾼 파일, 캡처 경로(레퍼런스와 나란히), 게이트별 통과·실패와 근거, 실제 GPU 확인 여부, 남은 문제.
